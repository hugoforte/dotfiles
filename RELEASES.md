- `git-list-merged-branches` and `git-delete-merged-branches` count a squash merge as merged. Both asked `git branch --merged`, which answers ancestry only — a squash replaces the branch with one new commit that shares no sha with it, so on a repo that squashes, which is every repo here, the helpers reported nothing and merged branches piled up unnoticed. `Get-BranchMergeVerdict` returns `ancestor`, `squash` or `no`, comparing the branch's net patch against every patch the target gained since the branch left it; the delete needs that distinction because git refuses `branch -d` on a squash-merged branch, so those go with `-D` and the prompt says so first. Patch ids are taken with `--verbatim` through `cmd`, since the default normalises whitespace and PowerShell 5.1 does not pipe bytes between two native commands. `tests/Git.Tests.ps1` covers the three merge styles, a branch continued after its squash, a whitespace-only branch, a tag shadowing a branch name, `-TargetRef`, the remote scope, and the delete itself behind a new `-Yes`
